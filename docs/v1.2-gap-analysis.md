## Native declaration review

Reviewed SetupAPI, Configuration Manager, kernel32 and Winspool declarations. HANDLE/pointers are native-sized; DWORD/CONFIGRET are 32-bit; BOOL uses default four-byte P/Invoke marshalling. Sequential structs retain native x64 alignment (including DRIVER_INFO_6 FILETIME/ULONGLONG). SP_DEVICE_INTERFACE_DETAIL_DATA_W has cbSize 8 on x64 but DevicePath offset 4. SafeFileHandle and finally blocks close native resources. Synchronous calls remain in killed-on-timeout child processes. No new native APIs or vendor command framing are introduced.

References checked against Microsoft documentation: [interface detail](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetdeviceinterfacedetailw), [DeviceIoControl](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-deviceiocontrol), [EnumJobs](https://learn.microsoft.com/en-us/windows/win32/printdocs/enumjobs), [USB descriptor request](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ns-usbioctl-_usb_descriptor_request). USBPcap offsets/stages reviewed against [upstream USBPcap.h](https://github.com/desowin/usbpcap/blob/master/USBPcapDriver/include/USBPcap.h).

PnP and spooler are Windows metadata, hub-driver-key is host metadata, printer IOCTL success is a driver response, and USBPcap is host-controller evidence. None alone proves a physical bus acknowledgement. Custom vendor interface GUID discovery and automatic identity across USB address reuse remain deferred: insufficient evidence must remain visible rather than guessed.
