# Implemented read-only commands

The only permitted device queries are the two entries below. Neither uses `WriteFile`, `WritePrinter`, print jobs, arbitrary endpoint transfers or vendor-specific command bytes.

| Registry ID | Host operation | Input bytes | Output buffer and interpretation | Limitations |
|---|---|---|---|---|
| `ieee1284` | `DeviceIoControl`, `IOCTL_USBPRINT_GET_1284_ID`, `0x00220034` | Empty (`NULL`, length 0) | Up to 4094 bytes. IEEE 1284 big-endian two-byte total-length prefix followed by semicolon-separated key/value fields, possibly NUL terminated. Original returned bytes are logged. | Requires accessible USB printer interface. Unsupported by some vendor drivers; length mismatches produce parsing warnings. Serial fields are accepted only from the response. |
| `port-status` | `DeviceIoControl`, `IOCTL_USBPRINT_GET_LPT_STATUS`, `0x00220030` | Empty (`NULL`, length 0) | Four-byte DWORD per Microsoft's ABI. Decode low-byte bit 3 = not-error, bit 4 = selected, bit 5 = paper empty. Preserve all returned bytes. | Generic printer-class indications, not disc-publisher mechanism/ink state. Other bits are not interpreted. Short responses are unavailable. |

Default query timeout is 5 seconds. Both commands are read-only and idempotent; neither is automatically retried. Request logs record the host IOCTL number and **zero input bytes**. Those numbers are not serialized as outgoing USB payloads. The driver constructs any class control setup packet; the app does not fabricate or claim to observe that packet.

## Primary sources

- [Microsoft: GET_1284_ID](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbprint/ni-usbprint-ioctl_usbprint_get_1284_id): input/output contract and recommendation to limit the buffer to 4094 bytes on affected devices.
- [Microsoft: GET_LPT_STATUS](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbprint/ni-usbprint-ioctl_usbprint_get_lpt_status): input/output contract, DWORD output.
- [Microsoft Windows SDK usbprint.h snapshot](https://github.com/tpn/winsdk-10/blob/master/Include/10.0.16299.0/shared/usbprint.h): numeric IOCTL definitions, `CTL_CODE(FILE_DEVICE_UNKNOWN, 12/13, METHOD_BUFFERED, FILE_ANY_ACCESS)`.
- [USB-IF Printer Class 1.1 specification](https://www.usb.org/sites/default/files/usbprint11a021811.pdf): GET_DEVICE_ID, length prefix, identification fields and Table 3 port-status bits. Direct class setup requests are **not sent** by this application.
- [Microsoft: identifiers generated by USBPRINT.SYS](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/identifiers-generated-by-usbprint-sys): Windows identity derivation; metadata is not independent proof of a live USB exchange.
- [Microsoft: PRINTER_INFO_2](https://learn.microsoft.com/en-us/windows/win32/printdocs/printer-info-2): spooler status flags.

## Other host read operations

SetupDiGetClassDevs / SetupDiEnumDeviceInfo / SetupDiEnumDeviceInterfaces / SetupDiGetDeviceInterfaceDetail / SetupDiGetDeviceRegistryProperty / SetupDiGetDeviceInstanceId enumerate present nodes/interfaces. CM_Get_Parent / CM_Get_Device_ID / CM_Get_DevNode_Status obtain ancestry and problem codes. Driver provider/version are read from the node's driver class registry key. EnumPrinters level 2 reads local candidate Epson queues/status. These host metadata calls have no application-controlled USB request bytes and are not represented as device commands.

No verified PP-100-specific identification/status protocol was established by the referenced public material. ESC/P, ESC/P2 and ESC/P-R bytes are therefore not sent. The application cannot interpret fatal-error history or derive a firmware version from an unverified REV field.
